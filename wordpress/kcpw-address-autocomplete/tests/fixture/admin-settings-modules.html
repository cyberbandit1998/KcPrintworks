Every feature below is off until you switch it on, and nothing here changes how the address suggestions themselves work. Switch them on one at a time while the plugin is in Preview, and test your checkout between each. Each one loads its own small file only on a page whose form uses it, so a checkout that uses none of them downloads none.

PO box notice
What to do about a PO box

Needs no Google service. "Refuse" is enforced by your server when the order is placed (classic checkout and the Checkout Block), only while the plugin is Live. It has not been run against a real WooCommerce here: try it on a staging copy first.

Address check

Advice only: it never stops an order. Needs the Address Validation API and the server key below. Google bills each check; repeated addresses are answered from memory, and a daily limit applies.


Used only by your server, never sent to a browser. Create a second key in Google Cloud, restrict it to the Address Validation API and to your server's IP address (not to websites). You can also set KCPW_AA_SERVER_KEY in wp-config.php. The test makes one real, billed check of a Google address.

A ceiling on what the address check can cost in a day, whoever asks. At the limit it simply says nothing.

Use my location

Only when the customer presses it, and the browser asks their permission first. Their position goes from their browser to Google's Geocoding service, nowhere else; it is not stored. Needs the Geocoding API.

Choose on a map

Opens a window with a Google map only when pressed. Works with a mouse, touch or the keyboard. Needs the Maps JavaScript API (a map load is billed) and the Geocoding API.

Google's markers need a Map ID. "DEMO_MAP_ID" works for testing; create your own free one in Google Cloud (Map Management) for production.

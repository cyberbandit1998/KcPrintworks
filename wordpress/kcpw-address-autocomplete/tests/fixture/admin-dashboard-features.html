    Google setup: APIs, key and billing

    1. A Google Cloud project with billing turned on. Google Maps Platform requires a billing account even when your use stays inside its free monthly allowance. The allowance and prices change: read the current ones before you go live. Google Maps Platform pricing
    2. Turn on these APIs (API Library): Maps JavaScript API and Places API (New) are required. Geocoding API is only needed for the optional map picker and "use my location". "Address Validation API" is only needed for the optional address check, and that one is called from your server with a separate server key (Settings > Features).
    3. Create a browser key (Credentials). Under "Application restrictions" choose "Websites" and add your shop address, for example https://shop.kcprintworks.com/*. Under "API restrictions" allow only the APIs above. A browser key is visible to visitors by design; the restrictions are what keep others from using it.
    4. Set a spending limit In Google Cloud, set a budget alert and a daily quota for the Places API. That is the only limit nobody can bypass; the plugin's own pause after a number of requests is a courtesy.

    How the plugin keeps the cost down: Google is contacted only when a visitor first clicks into an address field, never when a page loads. Requests wait for a pause in typing and for at least a few characters. One session token covers a whole typing session. Repeated text is answered from memory. After a choice it asks only for the address parts. After a failure it stops asking on that page.

    Google's terms: The list shows "Powered by Google" next to the suggestions. Keep it: Google's terms require it when suggestions are not shown on a Google map, and there is deliberately no setting to hide it. Google Maps Platform terms
